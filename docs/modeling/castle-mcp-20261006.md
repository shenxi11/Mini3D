## 执行方式与验证

使用已验收的本机包启动独占 Mini3D 实例，官方 SDK 2.3.1 连接项目 MCP stdio adapter。
全部场景创建、对象删除、灯光调整、视角控制、截图、保存和重新打开均使用实际 MCP 工具。
几何脚本只生成 `mesh.create` 的点面输入，没有直接写入工程格式、借助外部建模软件或操作鼠标键盘。
未使用电脑操控技能，也未修改 Mini3D 源码、接口限制或永久 Codex MCP 配置。

完成两轮 MCP 保存后重新打开；最后一轮逐一查询 72 个源网格，顶点数和面数全部一致。
最终文档 `isModified=false`，无交互忙碌，工程留在本次启动的 Mini3D 窗口中。
四个 PNG 都来自 `viewport.capture` 返回的 MCP image content，尺寸为 1178×736，
逐张核对 PNG SHA-256 与工具返回值；主代理实际看图检查了轮廓、入口、桥洞和取景。
另有未负责建筑实现的 Sol 请求代理只读复核四视角，认为可以作为风格化城堡交付，
指出亮部偏白及背面偏暗；随后主光由 1.35 降到 0.95，并重新保存、重开和捕获。
指定的子代理模型/推理启动参数已请求，底层 provider 实际路由没有独立证据，标记为未验证。

## 已处理的问题与边界

首次接入发生实例描述文件尚未就绪的启动竞态，确认本体存活及文件出现后添加就绪检查。
首次源网格全局焊接把相邻独立实体接成了三面共边；失败没有创建半成品网格，
改为单个几何单体内部共享身份、单体之间保持独立，并增加提交前边邻接检查。
反复关闭和重建 adapter 触及四个会话的短期保留上限；等待已知会话保留期结束，
最终用连续连接完成完整更新和验收，没有扩大上限或重放结果未知的写入。

第一版工程为 160,925,209 字节。为满足 MCP 重开上限，减少重复砖缝、瓦片、花草曲面分段，
建筑平面使用内核生成的法线而不是存储重复逐角法线，保留主要外形和色彩。
法线精简后的桥梁脚本曾残留一次对已删除 normal 属性的访问；在场景写入前失败，
删除该残留后重新做几何预检，再提交正式轻量版。

这是分组组合的建筑模型，不承诺整个城堡经布尔合并为一个封闭实体，也未验收 3D 打印。
当前渲染使用单一方向灯和顶点颜色；背面受光较暗，无参考图的写实纹理、烘焙阴影或复杂 PBR。
未重新运行与本次建模无关的 C++/TypeScript 全量测试；验收针对实际 MCP 场景流程和交付几何。
