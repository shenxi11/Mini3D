# Mini3D 原生动画需求草案与外部 AI 调研任务书

版本：Draft 0.1

日期：2026-10-07（Asia/Shanghai）

状态：供用户和其他 AI 调研、评审，尚未冻结范围，不是已实现功能或开工授权。

本轮交付：需求文档；不修改软件代码、场景格式、API/MCP 合同或用户配置，不提交 GitHub。

## 1. 业务结论与范围假设

建议先接入“场景对象与实体相机的原生关键帧动画”，使 Mini3D 能独立创建、编辑、播放、保存和重开动画，并允许 AI 通过现有本机 MCP 体系编辑关键帧、观察指定帧。

“原生”指动画是工程内的正式数据，由应用根据时间确定性求值。不是外部脚本持续调用普通对象变换，也不是回放建模历史或将截图拼成 GIF 来冒充动画支持。

当前用户要求先构思需求，再交其他 AI 调研。以下优先级、默认值、预算与技术方向均为建议；调研负责验证可行性和收敛设计，实施前另行确认。其中涉及场景格式、核心 API 合同和运行状态协调的改动不能仅凭本草案自行施工。

范围假设：首版重点是城堡、军事基地、机械模型的刚性部件运动与镜头演示，不是柔性人物表演。如果用户期望首版就包含骨骼、蒙皮或高达角色 IK，须重新冻结范围，不能把本方案当作满足该需求。

## 2. 当前实现基线

以下是本轮本地只读核对的事实，不是外部技术调研结论。

| 已确认情况 | 对动画需求的影响 |
| --- | --- |
| C++20、Qt 6 Widgets、OpenGL 4.1 Core；Core 不依赖 Qt/OpenGL | 动画数学与数据宜在纯 Core，计时与控件在 Editor，GPU 生命周期仍在 Renderer |
| SceneNode 使用稳定 EntityId，具有局部位置、四元数旋转和缩放 | 动画绑定对象 ID，不能绑定名称、树行号或裸指针 |
| 右手 Y-up，局部矩阵为 T × R × S，世界矩阵为 ParentWorld × Local | 首版采用局部动画通道，沿用父子层级，不改坐标系 |
| 缩放分量绝对值须至少 0.001；允许负缩放 | 关键帧合法不代表插值区间合法，必须处理跨零风险 |
| Inspector 把四元数还原为 Euler 度数显示 | 不能靠现有四元数往返保留 360°、720° 等连续转数 |
| 唯一 QUndoStack；正式对象/网格变更走提交和版本边界 | 动画编辑复用历史，播放/拖时间不得逐帧提交命令 |
| 当前工程写格式 3、读 1/2/3，原子保存及失败打开保护已存在 | 新动画必须有明确格式升级与旧稿保护策略 |
| 当前没有原生动画数据、时间轴或关键帧功能 | 这是新模块，不是解锁已有时间轴占位控件 |
| glTF/GLB 导入器明确拒绝 animations/skins | 原生动画首版不等于自动支持外部动画导入 |
| 47 项 API/MCP 方法；显式文档与版本、单应用线程、默认关闭本机桥 | 新动画能力须沿用合同与权限，不另开远程动画服务 |
| viewport.capture 已返回真实 PNG 与帧、视图版本和上下文信息 | 需补足动画时间与求值身份，防止拿上一动画帧冒充指定帧 |
| 实体相机预览已有独立规则，方向光仍为单有效灯 | 相机运镜需使用动画后的设备姿态，不能只移动保存用的编辑观察视角 |
| 底部已有控制台，Ctrl+Space 已用于区域最大化；Edit 中 I 是内插 | 时间轴与键位不能覆盖已有功能或把文本输入当命令 |

已有城堡与基地作品位于本地 `models/`，目前未提交到 GitHub。部分对象将多个部件合并为一个源网格，且旋转原点不一定在部件中心。不能假定当前直升机已有独立旋翼对象。首版可用专门的小型动画夹具验收；将已有作品拆件或重新建模是另一个任务。

## 3. 目标场景与成功标准

### 3.1 用户场景

| 场景 | 用户应能完成的动作 | 首版判定 |
| --- | --- | --- |
| 车辆沿道路行驶 | 两个或多个位置关键帧，拖动时间检查中间位置 | P0 |
| 门扇、雷达、机械关节转动 | 用独立对象/Empty 父节点作为转轴，编辑局部旋转 | P0；不提供自动找铰链 |
| 旋翼或轮轴持续转动 | 输入超过一圈的角度，播放多圈，无倒转或停转 | P0 关键验收 |
| 整体移动且部件单独运动 | 父对象平移，子部件局部旋转，运动正确组合 | P0 |
| 相机巡游 | 对实体 Camera 的位置与旋转设关键帧，在该相机中播放 | P0；不提供自动路径/跟随约束 |
| AI 制作动画 | MCP 写关键帧、查询轨道、跳指定帧并拿到真实图片 | P0 |
| 人物动作与柔性变形 | 骨架、蒙皮、IK、Shape Key 等 | 非首版范围 |

### 3.2 首版闭环

用户无需外部控制脚本即可完成：选择对象 → 设置动画范围和帧率 → 编辑当前帧姿态 → 插入关键帧 → 查看中间帧 → 播放/暂停/循环 → 调整或删除关键帧 → 撤销/重做 → 保存 → 重开后再次播放。

AI 无需电脑操控或任意代码执行入口即可完成同一闭环。指定同一工程内容、动画定义与时间，GUI、Core 求值、MCP 查询和截图必须使用相同姿态语义。

## 4. 功能范围与优先级

### 4.1 P0：原生动画首版必须完成

| 编号 | 需求 | 可验收结果 |
| --- | --- | --- |
| AN-01 | 场景级单一时间轴 | 可编辑起止帧、帧率；显示当前帧、动画预览与播放状态 |
| AN-02 | 对象局部 TRS 动画 | 原生基础体、静态导入节点、可编辑网格对象、Empty、Camera 和 Light 可按相同规则绑定变换轨道 |
| AN-03 | 手动关键帧录入 | 位置/旋转/缩放三个组可分别插入；同对象、组、帧的重复录入是显式替换，不生成重叠关键帧 |
| AN-04 | 关键帧管理 | 查询列表、选择、数值修改、删除、移动到指定帧；移帧遇占用须明确拒绝或显式替换，不能暗中覆盖 |
| AN-05 | 基础插值 | Constant 和 Linear；精确命中关键帧、范围外保持端值、未绑定组使用基础值 |
| AN-06 | 连续多圈旋转 | 0° → 720° 保留两个完整转数；不可用最短弧四元数插值把该运动压成静止 |
| AN-07 | 原生播放 | 播放、暂停、回到起始帧、前后单帧、循环；播放按实际经过时间推进 |
| AN-08 | 时间拖动与姿态预览 | 任意合法帧跳转；暂停停在当前姿态；退出动画预览恢复基础场景 |
| AN-09 | 帧姿态编辑 | 暂停时有明确的“编辑当前帧姿态”入口，允许数值或 G/R/S 草稿，确认写入关键帧，取消不改基础数据 |
| AN-10 | 层级与实体相机 | 父子同时动画，包围盒/框景/选择与显示一致；相机预览采用求值后的相机和父链 |
| AN-11 | 文档与历史 | 正式动画编辑进入唯一撤销栈；保存/重开保留定义，播放和跳帧不制造脏状态 |
| AN-12 | 对象生命周期联动 | 删除/复制含动画对象时同步处理轨道；Undo/Redo 恢复正确对象与动画身份 |
| AN-13 | API/MCP 接入 | 显式轨道读写、求值、跳帧、播放控制；不依赖 GUI 当前选区或输入框 |
| AN-14 | 指定帧真实观察 | MCP 截图绑定动画时间及求值状态；不能只更新数字就返回旧图 |
| AN-15 | 兼容与回归 | 旧工程原样打开；无动画时原建模行为不变；主体构建不自动编测试或运行 npm |

Light 在 P0 中仅沿用对象变换轨道：其旋转可影响光方向，位置/缩放不改变现有方向灯特性。此项不引入多灯叠加或灯参数动画。

### 4.2 P1：首版闭环稳定后另行评估

- 自动关键帧录入：显式开关、默认关闭，单次操作只产生一条历史。
- Ease In/Out、逐 XYZ 通道编辑与简化曲线视图；不把完整 Graph Editor 偷渡进 P0。
- 可见性离散关键帧、相机 FOV、方向灯颜色/强度动画。
- 时间轴关键帧多选、复制、拖动缩放时间范围和前后关键帧跳转。
- 受控 PNG 序列导出：明确输出目录、范围、分辨率、取消、部分产物与资源预算。
- 静态节点 TRS 的有限 glTF 动画导入/导出，须单独冻结兼容子集。

### 4.3 首版明确不做

骨骼/蒙皮、IK、约束系统、Shape Key、顶点/拓扑动画、修改器参数动画、物理模拟、粒子、布料、流体、音频、视频编码、视频剪辑、多场景/多 Clip/Action/NLA、完整曲线编辑器、任意脚本执行、自定义 Shader、材质节点或渲染特效。

这些是后续范围，不应预建插件框架、任意属性路径、通用事件总线或游戏引擎式动画图。内置动画也不自动赋予 3D 打印或网格水密保证。

## 5. 时间、通道和插值语义

### 5.1 时间模型

- 建议默认帧率 24 fps、范围 1–250、当前帧 1；这是产品默认值候选，不是现有行为。
- P0 的用户关键帧落在整数帧；内部实时播放允许子帧，才能让旋翼平滑运动。API 必须声明时间单位，不混用“秒”“帧”和毫秒。
- 建议帧率为整数 1–120、合法时间域 1–100000，endFrame ≥ startFrame；最终上限由调研结合数值精度和预算确认，不能无上限分配时间数组。
- 时间原点建议 `seconds = (frame - 1) / fps`，持续时间为 `(endFrame - startFrame) / fps`。具体循环端点语义必须冻结，避免把 1–25、24 fps 错当成 25/24 秒。
- 修改 fps 保持关键帧的帧号不变，因此改变秒数；不自动重采样或移动关键帧。
- 改小播放范围不删除范围外关键帧。按指定时间取样仍须得到同一结果，列表要提示范围外键。
- 非循环实时播放到末帧停下并呈现末帧。循环允许丢弃已错过的显示帧，不能因卡顿放慢动画时钟；循环何时显示末帧与回绕规则由调研给出可测试定义。
- 单帧范围可取样、预览，但播放应明确无时间跨度，不高速空转。
- 首版不新增负帧、倒放、时间重映射或可变帧率。

### 5.2 通道模型

- 一份场景动画定义；每个 EntityId 最多一组 Position、一组 Rotation、一组 Scale 轨道。
- 首版按 XYZ 整组存关键帧，避免单轴混合控制带来的 UI 和语义复杂度；没有轨道的组始终使用对象基础值。
- 第一键以前保持第一键，最后一键以后保持最后一键；没有键的轨道等价无动画，不得用零值覆盖基础值。
- 每个键明确声明到下一键的插值方式；最后一个键的插值对尾部保持不产生影响。
- Constant 使用左键值直到下一键，精确到达下一键时切换；Linear 使用相邻帧比例计算，不依赖播放次数或上一帧。
- 相同对象、通道、帧必须唯一；删除该组最后一个键后恢复基础值。

### 5.3 旋转：必须解决多圈问题

建议动画 Rotation 轨道保存“连续、未折叠的 Euler XYZ 度数”，求值时再转换为当前 Transform 使用的单位四元数。静态对象仍可保留原四元数，不应为了动画改写所有旧旋转数据。

这是技术候选而非已冻结的数据结构。调研必须验证旋转顺序、GLM 转换、万向节锁和现有 G/R/S 编辑兼容，并比较“连续 Euler”与“Quaternion 加显式转数/轴”两条最小可行路径。只有最终能稳定表达多圈且用户可理解的方案才能通过。

业务语义要求：

- 1 帧 Y=0°、49 帧 Y=720°，24 fps 下 2 秒转两圈；25 帧应为 360°，不能被当作 0° → 0° 的静止插值。
- 保存、重开、Undo/Redo、API 查询均保留 720°，不能从四元数还原后丢失转数。
- 170° → 190° 应向前转 20°；170° → -170° 的连续角模式应按显式数字转 -340°，不能暗中改成最短弧。
- UI 必须说明角度方向、局部轴和旋转顺序，提示多轴 Euler 的限制，不宣称具有 IK 或航向保持约束。
- 未绑定 Rotation 的对象保持基础四元数，不进行不必要的 Euler 往返。

### 5.4 缩放与有限值

- 沿用基础 Transform 的有限值和每分量绝对值 ≥0.001 约束。
- Linear 区间相应分量必须同号，拒绝 +1 → -1 这类中间穿零的段；Constant 可直接跳到另一合法符号，不能自动转成另一种插值。
- 保存/打开和插值方式修改同样校验区间；不能只在每帧崩溃后临时夹紧缩放。
- 候选值必须验证合法局部姿态及实际父链/世界结果；非法输入或不可用求值明确失败，不安装半份姿态或回传 NaN/Infinity。
- 不把动画世界矩阵分解成 TRS，不改既有非均匀/负缩放语义。

## 6. 原生编辑与播放交互

### 6.1 工作台

- 增加可显示/隐藏的中文“时间轴”区域；保留现有控制台入口，不删除控制台或重建 GL 视口。
- 时间轴包含播放按钮、当前帧、起止帧、帧率、循环、动画预览开关，以及当前对象的三组轨道与关键帧列表。
- 对象通过既有大纲选择，首版不新增多对象选择系统。轨道显示绑定对象名称和稳定身份，改名不丢动画。
- 关键帧有明确插入/替换/移帧/删除入口；可通过数值字段完成操作，不要求 P0 同时实现完整 Dope Sheet 拖拽。
- 属性区别“基础值”“当前求值值”“当前帧草稿”，动画绑定和当前帧有键的状态应可辨识，不只靠颜色表达。
- 100%/150%/200% 缩放、键盘焦点、中文输入法和窗口最小尺寸要纳入后续验收。

### 6.2 三种状态

1. 基础建模：动画预览关闭，原有 G/R/S、组件编辑、F9 和保存规则保持；改基础 TRS 不自动生成键。
2. 动画预览：按当前时间显示求值姿态。播放期间禁用数据编辑与 Undo/Redo，允许不影响数据的观察；暂停保留当前帧，不恢复基础值。
3. 当前帧姿态草稿：只在暂停的普通编辑视图中进入。数值/G/R/S 编辑草稿；“插入/替换关键帧”确认后写正式轨道，一次历史；Esc/取消丢弃草稿并回到当前帧已确认求值。首版不自动录键。

草稿期间不能切帧、播放、打开/新建、开始组件建模或另一个模态操作；应提示先确认/取消，而不是暗中提交。选区或焦点变化不得偷偷丢掉草稿。相机只读预览可播放，但不在其中开启 G/R/S 草稿；返回普通观察视图后再编辑相机姿态。

插入一个通道组不能改动另两个组。一次草稿确认可录入所选多个组，但仍是一条历史。单纯查看姿态、选择对象和跳帧不清空 redo。

### 6.3 键位与编辑安全

- 优先提供按钮、菜单与 F3 搜索入口；Space 播放/暂停、Object 模式 I 插键仅是候选，需要按现有 KeymapRouter 的区域和模式做冲突核对。
- Edit 中 I 继续内插，Ctrl+Space 继续区域最大化；文本编辑、IME、模态对话框优先，不由动画抢走空格、I、Delete 或 Esc。
- 进入 Edit/F9/组件操作前关闭动画预览并使用基础姿态；草稿/播放中拒绝切入，不默默取消原操作。
- 编辑基础网格不自动改动画键；播放只改对象求值姿态，不能逐帧执行 Mirror/Subdivision 或重新上传不变的源网格。
- 隐藏/局部隔离沿用现有规则；隐藏不是暂停对象动画或删除轨道。取消隐藏后应直接呈现当前时间姿态。
- 最小化/不可见时暂停实时播放，恢复窗口不自动补跑；单调时间基线在下次播放重置。

### 6.4 转轴与模型准备

P0 沿用对象局部原点，旋转轴通过既有父子层级和 Empty 表达。不提供从合并网格自动识别旋翼、轮子、门扇的功能。

动画夹具建议“移动父 Empty → 机身对象 + 旋翼轴 Empty → 独立旋翼对象”。演示人员先保证几何坐标与转轴一致，再录入局部键。现有大型军事基地仅作为可选复杂场景，不能覆盖或自动拆改用户原工程。

## 7. 数据、预览、撤销和对象生命周期

### 7.1 不可混淆的三类数据

- 持久基础场景：对象基础 TRS、网格、设备、层级等。
- 持久动画定义：范围、fps、对象绑定、关键帧值与插值。
- 会话预览状态：是否预览/播放、当前时间、循环开关、临时求值姿态与草稿。

建议 P0 保存前两类；打开后默认预览关闭、时间回到起始帧、非播放状态。不保存播放器时钟、草稿、当前播放帧、Undo 栈或 GPU 缓存。是否以后保存最后查看帧不属于首版必要功能。

### 7.2 一致性要求

```text
基础场景 + 动画定义 + 明确时间
                 ↓ 确定性求值
         同一份有效姿态/世界结果
                 ↓
    网格显示 / 相机与灯 / 包围盒与选择 / 帧查询与截图
```

渲染器、RayCaster、框景、选中线框和设备方向不能各用一套基础/动画矩阵。MCP 普通对象查询保留现有基础数据语义；若要读取动画姿态，使用显式取样或清楚标注的 evaluated 数据，不让 `entity.update` 从求值结果误写基础值。

动画覆盖与现有组件/Object 预览不能同时接管对象。采用临时求值快照还是变换覆盖表由调研确定；禁止把普通 setTransform 循环当成播放架构，也不为播放复制所有网格/GPU 资源。

### 7.3 历史与保存点

- 关键帧/轨道/范围/fps 的正式变更进入同一个 QUndoStack，并推进正式内容与历史版本。
- 播放、暂停、跳帧、循环和预览开关只改变会话状态；不改变基础 TRS、documentRevision、historyRevision、保存点或 redo 分支。
- 姿态草稿不标记正式文档；确认录键后才标脏。相同键和值录入返回 no_change，保留精确值与 redo。
- 保存写基础场景和动画定义，不能把当前预览姿态烘焙成基础值；有未确认草稿时拒绝保存并提示处理草稿。
- Undo/Redo 后重新求值当前时间，不回退单调身份/版本。播放中先由用户/API 暂停，再允许历史操作。
- 已有编辑观察相机导航会参与未保存判断，这一既有规则保留；“播放不标脏”的验收须隔离实际导航变更，不能误判。

### 7.4 对象操作

- 改名不影响轨道；删除子树同时删除其轨道，一条历史，撤销恢复原对象 ID 与动画数据。
- 复制子树同时复制其轨道，按新 EntityId 映射绑定；复制出的动画与源可独立编辑，redo 不重新分配身份。
- 首版建议拒绝对含动画绑定的子树执行换父，提示无法保证整段世界运动；允许先备份、明确移除该子树动画后再换父。不自动烘焙 keepWorld。
- 无动画子树的换父保持现有 keepLocal 语义，不为普通操作引入无关限制。
- 新建/成功打开清空旧预览与旧句柄；失败打开保持原文档、动画、当前时间、历史与选择。
- 集合不是动画父节点；集合显隐和对象临时显隐不修改动画定义。

## 8. 工程格式与旧版兼容要求

优先建议新增场景格式 4：动画新版本统一写 4，读取 1/2/3/4；不在格式 3 中静默加入可能被旧程序忽略并丢失的动画。调研须比较“无动画仍写 3”的兼容收益与双写策略成本，冻结方案后才能改合同。

必须满足：

- 旧 1/2/3 工程打开后保持基础模型与外观，不自动生成轨道、转换网格或改轴向。
- 旧工程首次升级须另存新路径，取消不改原件；MCP 同样不能绕过路径保护。
- 格式 4 保存动画定义，不保存求值缓存、当前帧草稿、Undo 栈和运行版本。
- 未知/不支持的版本、通道、插值、非法对象引用、重复绑定/键、非有限值、错误时间或跨零缩放段使整次打开失败，不局部吞掉坏轨道。
- 用小型中立 JSON schema 与 Core 语义校验说明精确合同；两者通过不能替代真实文件保存/重开验收。
- 保留 QSaveFile 原子写入、相对资源路径与现有依赖/文件预算；不改成逐帧缓存文件，也不改安全读写根。
- 静态格式与 API 四元数顺序现有差异（文件 WXYZ、API XYZW）必须继续明确，不能把动画欧拉值误当四元数数组。
- 不要求动画导出为旧格式；若提供另存旧版，必须另立明确丢失提示与授权，不能静默去掉动画。

## 9. API/MCP 候选能力与边界

本节是后续接口调研输入，不表示方法已存在。方法名/版本/字段需在方案冻结后再定；新增方法不能直接挤进 API 0.1.0 而不说明协商、schema 和客户端兼容。

| 候选能力名 | 类别 | 必须明确的输入/效果 |
| --- | --- | --- |
| animation.getState | 查询 | 文档身份、范围/fps、播放/预览/时间及会话求值身份；播放中仍可读 |
| animation.listTracks / readKeyframes | 查询 | 显式 EntityId/通道、稳定排序、分页与定义版本，不读取 GUI 选区 |
| animation.setSettings | 内容修改 | 范围/fps，全量候选先校验，一条历史，不删范围外键 |
| animation.upsertKeyframes | 内容修改 | 显式实体、通道、整数帧、完整组值与插值；有界整批原子写入，一条历史 |
| animation.deleteKeyframes / removeTrack | 内容修改 | 明确键或轨道目标，完整验证后提交；no_change 不污染历史 |
| animation.moveKeyframe | 内容修改 | 明确原帧/新帧与占用处理，不静默覆盖；GUI/API 共用语义 |
| animation.sample | 只读求值 | 显式时间与对象集合，返回求值 local TRS/worldMatrix 与旋转通道原值，不改变 GUI 当前帧 |
| animation.setPreview / setFrame | 会话控制 | 明确文档、预期会话版本与时间；不改内容/历史，也不自动暂停正在播放的用户会话 |
| animation.play / pause | 会话控制 | 操作明确，不用单一 toggle；播放时 pause 必须可调用，不被自身 Busy 锁死 |
| viewport.capture 的动画感知扩展 | 真实观察 | 实际截图的时间/求值版本及当前真实帧；保留现有图片字节、SHA256、尺寸与超时校验 |

### 9.1 版本与运行状态

- 内容写入仍提供 document 与 expectedDocumentRevision，历史操作继续校验 historyRevision；ID/版本走规范十进制字符串。
- 建议单独使用会话播放/求值版本或等效 token，不以每帧 documentRevision++ 避免过期；新 token 的最终命名由调研确定。
- 已有对象查询的基础值语义必须保留；sample 明确是只读计算，不把取样当 GUI 预览更新。
- 批次预算沿用已有 envelope 和总内存预算；写键数量、轨道数、取样对象数、返回分页上限需显式限制并由 system.describe 宣告，不能开放无限批次。
- 播放期间拒绝普通内容写入及定义修改，并保留可暂停和可查询通路。动画预览暂停时是否允许普通对象/文件操作按第 6–7 节做一致守卫，不能同名 Busy 一刀切。
- 当前帧草稿拒绝外部写入和切帧；不抢 GUI 选择、不静默取消用户草稿。
- 冲突、Busy、非法时间/轨道、超预算均返回结构化原因，不能要求 AI 根据中文提示猜语义。

### 9.2 指定帧截图闭环

首版建议使用暂停 → setPreview → setFrame → 等待匹配实际绘制 → viewport.capture，不必先增加大而全的渲染导出任务系统。

必须提供可校验的内容版本、时间/求值 token 和真实 frameId。等待期间发生跳帧、定义编辑、文档切换或 Context 重建，应按明确合同拒绝过期请求或重新等待，不能悄悄返回另一时间的图。单看图片 hash 不足以证明其时间正确。

实时播放截图可明确拒绝并要求暂停；不能把“任意当前帧截图”宣传为指定帧截图。animation.sample 的成功仅证明 CPU 求值，不代表 GPU 已绘制。调研须对现有 ObservationService 和 MCP 图片验证路径给出最小兼容扩展方案。

### 9.3 保留原安全边界

只用现有默认关闭、同用户命名管道、指定实例、受控读写根和应用线程串行服务。不增加公网端口、远程服务、任意表达式/脚本、后台建模线程或 shell 执行工具。适配器只转译合同，不自己插值关键帧或持有另一套场景。

本草案不授权修改用户 MCP 配置、读取私有 instance 描述文件、上传模型/凭据或启动生产动画作业。性能验证使用隔离副本，不能覆盖已有作品。

## 10. 性能和实现约束（候选门槛）

- 同一时间求值结果不依赖前一帧；可直接跳到任意帧，不通过逐帧模拟抵达目标。
- 用单调时间驱动实时播放；Qt 定时触发只是唤醒，不是唯一时间来源；不阻塞 UI，不使用嵌套事件循环。
- 只刷新动画相关状态和重绘，不逐帧重建 SceneTree、所有输入框、网格、GPU 资源、Undo 命令或保存缓存。
- 不含动画且关闭预览时没有常驻高频播放定时器，原建模性能不应因新功能持续付费。
- 候选性能夹具：100 个动画对象、300 个通道组、共 9000 个键、约 5 万源点，24 fps 连续播放 30 秒；Release 同机记录求值 P95、实际帧间隔、内存和 UI 响应。
- 候选目标：纯动画求值 P95 ≤5ms；该固定夹具实际帧间隔 P95 ≤41.7ms。目标需调研确认或解释修订；不能以当前建模性能报告证明动画通过，也不能从轻量夹具保证所有大型场景实时播放。
- 超出播放能力仍按时间前进，可跳过显示帧并提示统计；指定帧取样/截图必须准确，不因性能降级改变键值。
- 不新增未经必要性论证的动画库、游戏引擎或第三方视频工具；先评估 Core/GLM/Qt 现有能力。

以下是未来开发完成时的验收要求，本轮仅核对需求，不宣称这些测试已运行。

| A14 API/MCP | 有界录键/改键/查询/取样/跳帧/真实图片 | 与 GUI/Core 数值一致；基础查询不被预览污染；版本、图片和帧身份匹配 |

| A16 指定帧竞态 | setFrame 后再跳帧/改键/重开/重建 Context | 旧 capture 不成功冒充目标帧；返回可诊断失效/超时 |

数值精度标准由调研给出坐标、角度、四元数与世界矩阵各自的误差界；不能用图片像素相等代替连续旋转数学，也不能仅以首尾相同的旋翼截图证明“转了两圈”。

验证分层：纯 Core 数学 → Editor 状态/历史 → 文件 → 实际 Qt/OpenGL 观察 → 真实 SDK/MCP；正常开发优先定向用例，整合阶段再跑受影响回归，不把测试绑到普通运行按钮。
