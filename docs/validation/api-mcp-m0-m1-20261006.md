### 正式 Schema 接官方 SDK 的结论

直接把带跨文件 `$ref` 的正式 `entityCreate` 交给 `fromJsonSchema` 会失败；通过公开 validator 注册三个 `$id` 文件虽能解析引用，但默认忽略 `uint64-decimal`，越界字符串 `18446744073709551616` 仍被接受。证据：`logs/contract-api-probe.json`；不得按该默认行为开放工具。

最小原型从正式三个 Schema 的 allowlist 出发，在内存展开有限、无循环的 JSON Pointer 引用，将 **同一个** `uint64-decimal` 格式派生为标准精确上界约束，再交官方默认 Draft 2020-12 `fromJsonSchema`。不是另一份 Zod 合同、不读取私有 Ajv 字段、不降 Schema draft，也没有新增包安装。

该路径已实际编译 27 个正式定义；同一份 `examples.json` 10 项、19 项 direct 校验、10 项内存 MCP 工具校验全通过、warning 为零。覆盖真实 uint64 上界与 max+1、未知字段、数字 ID、完整 create、过小 scale、零四元数、坏 UUID 和零序号；非法输入没有进入 handler。证据：`logs/contract-bridge-results.json`、`logs/contract-bundled-schema.json`。输出合同的最大版本/越界版本为合成校验样例，不能代替全部 C++ 实际响应的端到端 Schema 验证。

## 审查、复现与修复

独立 Sol 审查发现：同值旋转重新归一化会误入历史、破坏 redo；合法局部极大缩放可让 worldMatrix 溢出，JSON 成功响应不再满足 number 合同。

- 第一组定向红测 `[api-review-regression]`：构建成功后实际运行，3 cases / 43 assertions，4 个断言失败。日志 `api-review-red.log`。
- 主代理进一步发现仅改 translation/scale 的 Undo 也会重复归一化；第二组红测 `[api-transform-history-regression]`：1 case / 16 assertions，两个 SECTION 的断言失败。日志 `api-transform-history-red.log`。
- 修复采用保留未变化旋转、一次准备新旋转、精确安装已确认历史 TRS；原 `Scene::setTransform` 仍保留原归一化行为。JSON 解码不预先改变有效四元数。同值 no_change 保留 redo、cleanIndex 和两个版本。
- 世界矩阵或几何世界边界无法有限表达时，entity/list 返回 `UNSUPPORTED_TRANSFORM`，不输出 null 冒充矩阵元素、不把边界溢出伪装成空对象。
