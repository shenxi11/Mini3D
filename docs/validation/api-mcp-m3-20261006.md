## 失败证据与根因

1. 原另存最终guard竞争覆盖：有效red为2用例/37断言、8失败，其中保存7项，exe42（tests-m3-boundary-red.log）。改原子NewOnly后首次整合失败6个保存案例；tests-save-native-diagnose.log证实系统错误32。Qt6.8.3的QTemporaryFile::close只seek、不释放不共享DELETE的原生句柄。最终析构暂存对象、scope guard接管清理再MoveFileExW(flags=0)，成功/竞争拒绝/GUI替换均green。
2. 原高坐标focus产生NaN：合法单位Cube平移1e8有有效red；提交前验证相机保存状态和全部view/projection有限，当前观察集合通过。
3. 原Context rebuild后Qt函数表断言：diagnose-observation-2.log定位qopenglfunctions_4_1_core.cpp:56。每Context独立wrapper，先阻断观察、释放GPU、最后释放函数表；context绿色13用例/465断言，最终集合仍通过。
4. 原Qt-only权限不足证明local-only、descriptor本机持久ACL缺检和DELETE共享冲突：原生PIPE_REJECT_REMOTE_CLIENTS、实际SID/DACL与卷核验、驻留读写/分享读取及精确停止删除落实，Astra定点关闭。环境负测跳过不算实际跨主机通过。
5. 新监听满槽测第二次连接失败：tests-native-slot-console.log记录首次count1已达、第二connect Connection error。Queued补监听让同线程Qt在PIPE_BUSY阻塞而不能跑补监听；立即创建一个overlapped实例、完成仍由notifier驱动，4槽/第5拒绝/释放复用/三轮停止重启最终green。
6. 两次真实捕获CAPTURE_TIMEOUT：real-bridge-1791273817772及1791273866816/failure.json。隔离排除并行测试后仍复现，改GUI spawn的windowsHide为false后立即取得匹配新帧；SW_HIDE抑制首次展示。未通过增加sleep、延长期限或返回旧帧掩盖。
